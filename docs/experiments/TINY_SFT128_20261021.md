# 128 条 SFT 精度对照：实际结果

日期：2026-10-21。用户提交 `comparison.json`，原始副本为 `TINY_SFT128_20261021_comparison.json`。这是固定 train 子集的拟合诊断，不是 valid/test 结果。

## 对照条件核对

两组汇总中的起始 checkpoint、128 条样本、样本 SHA256、100 updates、LR=2e-5、有效 batch32、micro batch2、seed42、框架版本和 A800 GPU 名称均相同。样本哈希也与本地预先生成的清单一致：`f23410f8363165318a2522b85b4bca8258db2fd8cb32c1a3a8663849f3b23e3f`。

BF16 参数组报告 338 个 BF16 参数张量；FP32 参数组报告 338 个 FP32 参数张量。两组均采用 BF16 autocast，最后均导出为 BF16 进行相同 constrained beam10 推理。两组只训练 next-SID，无标题任务，从同一 E1 独立开始且新建优化器，不继承原优化器状态。

此次只收到汇总文件，未收到该运行的逐条预测、step10 profile、训练曲线和输入哈希文件；因此核对的是报告的控制条件与汇总内部一致性，没有独立重算逐条排名指标或验证服务器全部文件。实际 optimizer state dtype 待 profile 佐证，不由参数 dtype 直接代替。

不同预测 SID 可以超过128，因为每条有10个候选。它不是命中物品数或不同正确答案数。最常见 Top-1 在 FP32 组换成另一个 SID，表中比较各组自己的最高频占比。

122 条目标 SID 唯一的子集 HR@10：初始3/122，BF16组30/122，FP32组39/122。因而差异并非只来自6条碰撞目标。

FP32 相对 BF16 的 train HR@10 多命中10条，增加7.8125个百分点；未做配对显著性检验，没有多 seed 重复，不称为统计显著或泛化提升。

| b 层 teacher-forced top1 | 6.250% → 14.844% | 6.250% → 16.406% |
| c 层 teacher-forced top1 | 6.250% → 6.250% | 6.250% → 8.594% |

| c 层 teacher-forced top10，训练后 | 32.031% | 39.063% |

teacher-forced 后续层使用真实前缀，且此处是在完整词表上计算，不是受限生成的准确率。b/c 仍有明显拟合空间，不能说128条已被充分记住。

训练前 NLL 有约0.0037差异：同一 BF16 权重转换为 FP32 后，混合精度的实际数值计算路径并不保证逐位相同。不能要求两种精度的前向值严格相等。

Trainer 全过程平均 train_loss：BF16=2.568185，FP32=2.630669；但结束后的统一 eval 模式目标 NLL 是 FP32 更低。过程平均与最终 eval 指标不是同一量；缺少曲线时不推断平均值差异的具体原因，不只选取一个 loss 得出效果结论。

## 参数更新与资源

在导出 BF16 之前，BF16 组主干抽样仍有约69%–78%元素未变；FP32 组三处抽样基本全部变化。最终 norm 的不变比例：BF16=99.9349%，FP32=0%。目标 SID embedding 行的不变比例：BF16=29.7249%，FP32=0%。

这些结果与低精度参数更新受限的解释一致，但更多参数变化本身不是更好效果的充分条件；需要连同 NLL 与生成表现解释。两组的参数/相关优化器数值行为一起变化，尚未单独分离参数舍入与优化器状态精度的作用。

| 资源，仅训练阶段 | BF16组 | FP32组 |
|---|---:|---:|
| 训练耗时 | 131.78秒 | 149.07秒 |
| peak CUDA allocated | 14.41 GiB | 28.83 GiB |
| peak CUDA reserved | 16.38 GiB | 31.47 GiB |

FP32组本次训练耗时约增加13.1%，allocated约为2倍；在A800 80GB上可行。不是完整运行耗时，也不是完整三任务 SFT 的直接资源保证。

## 当前结论与后续动作

1. 两组短程训练都能改善同一小批样本，当前流程具有学习能力；不支持“BF16完全不能训练”。
2. 同一预算下，FP32参数组在最终NLL、生成命中和候选分散程度上表现更好，支持进一步验证精度配置对拟合的影响。
3. 这不能证明原完整SFT的唯一根因，也不能把34.375%当成完整valid效果，更不能作为Reward优化收益。
4. 推荐下一项正式实验：从原始Qwen2.5-1.5B Base重新运行完整三任务SFT，保持原数据、SID、seed、batch64、LR2e-5、3epoch、warmup3%、长度512和评估协议，主要改为FP32参数+BF16混合精度。保留旧E1，保存新实验目录；先profile，再完成全valid评估。不从128条过拟合模型继续做正式基线。
5. 以当前完整SFT约3.13小时和短程吞吐比作粗估，新完整训练可能约3.5–5小时，必须以新任务实测修正；尚未启动，也未假设租卡价格。
6. 若完整valid改善，再确定后续SFT基线并开展GRPO；若未改善，记录负结果，继续考察任务配比、数据和优化预算。
