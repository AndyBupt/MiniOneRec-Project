## Interpretation

Concentration persists on seen training examples. The inspected decoder graph has no blocked catalog paths; sampled backbone parameters changed, but their changes and unchanged final norm do not diagnose numerical rounding. Current evidence does not justify simply blaming overfitting, model size, or lack of GRPO. Training recommendation data can have ambiguous next-item targets; low training HR alone does not prove a bug or imply every interaction should be memorized.

## Next controlled experiment design (not launched)

Use a small fixed train-only subset (128 histories), audit loss masks and target alignment, and check that SID tokens remain supervised after truncation. Exclude histories with conflicting SID targets from this diagnostic subset, documenting that this makes it easier and unrepresentative of real recommendation.

From the same existing E1 checkpoint, run two isolated short next-SID-only fits: (A) existing BF16 parameter storage + AdamW, (B) FP32 parameter storage + BF16 autocast + AdamW. Keep sample IDs/order, seed, LR=2e-5, effective batch32 and 100 update steps fixed; no checkpoint continuation optimizer state in either arm. Start with 10-step profiling, record actual parameter and optimizer-state dtype, wall time and memory, then decide feasibility. Never overwrite E1. This is a precision/fitting diagnosis with changed task mix and repeated tiny data, not a production improvement or a fair replacement full-data baseline.

Compare pre/post target-token loss and teacher-forced a/b/c accuracy, deterministic generated HR@10 and candidate coverage on the same 128 rows, and parameter update statistics. Teacher-forced later-token accuracy uses gold earlier SID tokens and is not free-generation accuracy. Better FP32 behavior would support, not by itself prove, an update-precision explanation. If both fit, investigate full-data schedule/task mixing; if both fail, continue checking data/loss/optimization. Do not download a larger base or launch full GRPO based on this file alone.
